# Blinkpick v1 Implementation Plan

> **For Hermes:** Implement this plan incrementally using TDD. Update the progress table only after the recorded verification succeeds.

**Goal:** Build Blink as a portable Go CLI whose official executable is `blinkpick`: it selects a random, suitable Miniflux entry for interactive terminal discovery or noninteractive agent hooks.

**Architecture:** A single Go binary has four independent layers: configuration/state persisted in OS-standard local directories, a Miniflux REST adapter, a deterministic and testable selection engine, and two presentation paths. `blinkpick` opens a compact card TUI for humans; `blinkpick suggest` never interacts and emits text or JSON for hooks. Miniflux remains the source of truth for entries, read state, and saved/starred state.

**Tech stack:** Go, standard library where practical; `golang.org/x/term` for a tiny cross-platform card TUI and `golang.org/x/net/html` for safe HTML-to-text extraction. No daemon, database, GUI, web server, or RSS-management implementation.

## Scope and non-goals

### Included

- Config wizard (`blinkpick config`) for provider, Miniflux URL, username, and API token.
- Targeted noninteractive config updates (`blinkpick config --url`, `--username`, `--token`, `--provider`).
- Miniflux API token and HTTP Basic authentication support.
- Random entry selection with unread preference, freshness, reading-time preference, recent-entry exclusion, and recent-feed rotation.
- Card TUI with open-original, toggle-save, mark-read, next, help, and quit actions.
- `suggest --one-line|--json` for agent hooks; it must never prompt, open a browser, or emit terminal control sequences.
- Local JSON config/state and a `doctor` connectivity check.
- Unit tests plus a real local HTTP Miniflux-compatible integration check.

### Explicitly deferred

- Any GUI, browser app, daemon, notification system, or plugin installation.
- RSS / feed / category management.
- Multi-provider implementation (provider interface is documented only; Miniflux is the sole v1 provider).
- Article full-reader pager, offline content cache, AI summaries, accounts, or synchronization beyond Miniflux mutations.

## CLI contract

```text
blinkpick [selection flags]             # interactive card TUI
blinkpick suggest [selection flags]     # noninteractive output
blinkpick mark-read <entry-id>
blinkpick save <entry-id>
blinkpick unsave <entry-id>
blinkpick config [--provider P] [--url URL] [--username USER] [--token TOKEN]
blinkpick doctor
```

Selection flags: `--minutes`, `--category`, `--fresh`, `--all`. `blinkpick` must reject a non-TTY interactive invocation with a useful message directing callers to `blinkpick suggest`.

## State ownership

| Data | Owner | Blink behavior |
|---|---|---|
| feeds, categories, entries, read/saved status | Miniflux | query and mutate only through its API |
| URL, auth mode, username | Blink config | local-only |
| API token | Blink config, mode 0600 | environment token may override later; no token logging |
| recently suggested entry/feed IDs | Blink state | controls local repeat avoidance only |

## Detailed execution tasks

### 1. Establish module and test baseline

**Files:** `go.mod`, `cmd/blinkpick/main.go`, `internal/.../*_test.go`, `.gitignore`.

1. Install the official Go toolchain for the host using a command-scoped proxy only if the default path fails.
2. Create module `github.com/idealland-apps/Blink` and a minimal CLI that prints usage.
3. Add a failing unit test for command dispatch / usage, observe failure, then implement the minimum executable.
4. Run `go test ./...`, `go vet ./...`, and build a local binary.
5. Commit the baseline and update this plan.

### 2. Create testable domain, persistence, and picker

**Files:** `internal/model`, `internal/config`, `internal/state`, `internal/picker` and tests.

1. Write failing tests for config round-trips, default paths, atomic state persistence, freshness filtering, no-repeat exclusion, feed rotation, and minute preference.
2. Implement only the smallest types and pure picker functions to pass each focused test.
3. Use local state to record only delivered entry/feed IDs after a successful result.
4. Commit the verified core and update this plan.

### 3. Add Miniflux adapter

**Files:** `internal/miniflux` and tests.

1. Write `httptest` failures for token auth, basic auth, entry query construction, and read/save mutations.
2. Implement request/response conversion around Miniflux's `/v1/entries` and entry update endpoints.
3. Ensure API error messages identify status/action but never reveal tokens.
4. Commit the verified adapter and update this plan.

### 4. Add configuration UX and noninteractive commands

**Files:** `internal/cli`, config tests, README.

1. Define `config` behavior: bare `blinkpick config` opens the prompt-driven wizard; any supplied field flag applies a targeted update without prompts.
2. Wizard order: provider (currently only `miniflux`), URL, auth method (API key or basic), then required credentials; validate URL and write only after confirmation.
3. Add `suggest` plain, one-line, and JSON output; JSON remains machine-readable alone on stdout.
4. Add `doctor`, `mark-read`, `save`, and `unsave` commands.
5. Commit this noninteractive vertical slice and update this plan.

### 5. Add compact human card TUI

**Files:** `internal/tui`, `internal/render`, tests.

1. Write failing render/action tests first.
2. Render article metadata, extracted text preview, original URL, and the fixed key map: `o`, `s`, `r`, `n`, `?`, `q`.
3. `o` delegates to a small OS-specific browser opener; save/read wait for remote success before showing success; `n` requests another selection.
4. Use raw terminal mode only during the interactive session and always restore it.
5. Commit this verified slice and update this plan.

### 6. Release quality and documentation

**Files:** `README.md`, `.goreleaser.yaml` if justified, CI workflow only if it has a real tested command.

1. Document installation from GitHub Releases, configuration wizard, agent-hook outputs, security boundary, and all v1 non-goals.

## Risks and decisions

- **CLI collision:** Project name remains Blink; released binary is `blinkpick`. `blink` is already claimed by an npm AI-agent CLI and a Homebrew x86 emulator.
- **Credential storage:** v1 uses a mode-0600 config file, intentionally documented. OS keychain support is not required for first usable delivery.
- **Terminal content:** Blink is a discovery card, not a full HTML reader. It renders a safe short plaintext preview and sends full reading to the original URL.
- **Miniflux auth:** API token is the default recommended wizard path. HTTP Basic is supported for self-hosted setups where users prefer it.
- **Provider future:** A narrow `Provider` boundary may be introduced only where it reduces coupling; v1 should not implement empty adapters or a provider marketplace.

## Post-v0.1.0 portability revision

The release binary is intended to be copied between machines, so the default config and recent-pick state now live next to the executing binary as `blinkpick.config.json` and `blinkpick-state.json`. `BLINKPICK_CONFIG_PATH` and `BLINKPICK_STATE_PATH` remain explicit overrides for read-only system installs. The old OS user-config path remains a read-only fallback for existing v0.1.0 users.
