# Blinkpick Manual Release Automation Plan

**Goal:** Use GitHub Actions to build multi-platform Blinkpick binaries and publish a GitHub Release only when Anthony manually triggers the workflow from GitHub's web UI or the GitHub CLI.

**Architecture:** A single `workflow_dispatch` workflow accepts a required version tag and an optional prerelease flag. A build matrix compiles static Go binaries for Linux amd64/arm64, macOS amd64/arm64, and Windows amd64. A separate release job collects immutable artifacts and creates a GitHub Release using `gh`; no `push`, `pull_request`, tag-push, or scheduled trigger creates releases.

## Manual release contract

1. Merge this workflow into the default branch.
2. On GitHub open **Actions → Release Blinkpick → Run workflow**.
3. Select the source branch/commit in the UI, enter a new semantic tag such as `v0.1.0`, and optionally check prerelease.
4. The workflow runs tests, builds all six targets, uploads artifacts, then creates the Release and its tag only after all builds succeed.
5. Rerunning with an existing tag intentionally fails rather than replacing release assets.
